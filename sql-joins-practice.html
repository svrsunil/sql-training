Part 1: Joins

A JOIN combines rows from two or more tables based on a matching column. INNER JOIN keeps only rows that match in both tables. LEFT JOIN keeps every row from the left table, filling in NULL where there's no match on the right. RIGHT JOIN is the mirror of LEFT JOIN (keeps every row from the right table). FULL JOIN keeps everything from both sides, matched or not. CROSS JOIN returns every possible combination of rows from both tables (no matching condition at all). A SELF JOIN isn't a new keyword — it's just joining a table to itself, useful for comparing rows within the same table.

Part 2: Analytical (Window) Functions

GROUP BY collapses many rows into one row per group. A window function (OVER (...)) computes a value across a group of rows but keeps every row — nothing collapses. PARTITION BY defines the group; ORDER BY inside the OVER defines the order for running calculations. Any aggregate function — SUM, COUNT, MIN, MAX, AVG — becomes a window function just by adding OVER (...) after it.

Part 3: Putting It Together

This is the full query that rebuilds the business's Final Output report: net off damage, apply the stock-based price adjustment, convert to INR, and tag each row with its GL code — all in one query using a CTE. 

WITH damage_totals AS (
  SELECT contract_no, SUM(damaged_qty) AS damaged_qty
  FROM inventory_damage
  GROUP BY contract_no
)
SELECT
  c.contract_no,
  c.rm_description,
  c.shipper,
  g.gl_code,
  c.total_sop - COALESCE(d.damaged_qty, 0) AS pending_sop,
  ROUND(c.usd_rate * (1 + s.price_adjustment_pct), 2) AS adjusted_rate,
  ROUND(c.usd_rate * (1 + s.price_adjustment_pct) * cr.usd_to_inr_rate, 2) AS inr_rate,
  ROUND((c.total_sop - COALESCE(d.damaged_qty, 0)) * c.usd_rate * (1 + s.price_adjustment_pct), 2) AS sales_value
FROM contracts c
LEFT JOIN damage_totals d ON c.contract_no = d.contract_no
INNER JOIN stock_levels s ON c.rm_description = s.rm_description
INNER JOIN currency_rates cr ON c.contract_date = cr.rate_date
INNER JOIN gl_accounts g ON c.rm_description = g.rm_description
ORDER BY c.contract_date;

Exercise 21 — Indexing

Topic: Indexing — a lookup shortcut that speeds up searches and joins

contract_date is used in almost every join and filter on this page. Write the statement that creates an index on it, and explain in one sentence why that helps.

Hint

CREATE INDEX doesn't return rows — it changes how the database looks up data, so there's no "result table" for this one, just the statement and the reasoning.

Show Answer 
CREATE INDEX idx_contracts_contract_date ON contracts (contract_date);

Without an index, every join or filter on contract_date has to scan the whole table row by row. An index lets the database jump straight to matching rows instead — like using a book's index instead of reading every page to find a topic. Primary Key and Foreign Key columns are usually indexed automatically for the same reason.

Exercise 24 — NULL handling

Topic: NULL handling — NULL means unknown/missing, not zero

Using the LEFT JOIN result from Exercise 2, replace any NULL damaged_qty with 0 so the column is always a usable number.

Hint

COALESCE(value, fallback) returns the first non-NULL value it finds — treating "no damage record" as "zero damage."

Show Answer 
SELECT c.contract_no, c.rm_description, COALESCE(d.damaged_qty, 0) AS damaged_qty

Exercise 25 — Data types

Topic: Data types — choosing the right type avoids rounding and comparison bugs

Match each column below to the data type it should be stored as, and explain in one sentence why usd_rate should never be stored as plain text.

Hint

Money/rate columns need a type that supports exact decimal arithmetic — typically DECIMAL/NUMERIC, not FLOAT (which can introduce rounding errors) and never text.

Show Answer

contract_noVARCHARText identifier, never used in arithmetic

If usd_rate were VARCHAR, the database couldn't sum, compare, or calculate with it without first converting it — and a text comparison like '900' > '860' can even sort incorrectly, because text compares character by character, not as a number.

Topic: Subqueries — a query nested inside another query

Find every contract whose usd_rate is above the overall average usd_rate across all contracts.

Hint

Calculate the average in a subquery first (SELECT AVG(usd_rate) FROM contracts), then compare each row's usd_rate to that single value.

Show Answer 
SELECT contract_no, shipper, usd_rate
FROM contracts
WHERE usd_rate > (SELECT AVG(usd_rate) FROM contracts);

Exercise 27 — CTEs (WITH)

Topic: CTEs — a named, temporary result set that makes a query easier to read

Using a CTE, find contracts whose sales_value (total_sop × usd_rate) is above 700,000, without repeating that calculation in a WHERE clause.

Hint

Name the calculation once inside a WITH block, then filter against that name in the outer SELECT — the same pattern used for damage_totals in Part 3.

Show Answer 
WITH contract_sales AS (
  SELECT contract_no, shipper, total_sop * usd_rate AS sales_value
  FROM contracts
)
SELECT * FROM contract_sales WHERE sales_value > 700000;
contract_noshippersales_value
CN2001Golden Harbor Trading LLC850,000
CN2003Coastal Mart Distributors1,080,000

A CTE isn't a different feature from a subquery — it's the same idea, just named and placed up front so the main query reads top-to-bottom instead of nesting parentheses inside parentheses.

Cheat Sheet

Use this......when you want to
INNER JOINKeep only rows that match in both tables
LEFT JOINKeep every row from the left table, even without a match on the right
RIGHT JOINKeep every row from the right table, even without a match on the left
FULL JOINKeep every row from both tables, matched or not
CROSS JOINCombine every row of one table with every row of another (no matching condition)
SELF JOINJoin a table to itself to compare rows within the same table
GROUP BYCollapse many rows into one summary row per group
HAVINGFilter groups after aggregation (WHERE filters rows before grouping)
Window function (OVER)Compute SUM/COUNT/MIN/MAX/AVG/RANK/LAG/LEAD across a group without collapsing rows
DISTINCTRemove duplicate rows from a result
COALESCEReplace a NULL with a fallback value
Subquery / CTE (WITH)Break a complex calculation into a named, reusable step
Primary KeyGuarantee a column uniquely identifies each row
Foreign KeyGuarantee a column's value always exists in another table's Primary Key
IndexSpeed up lookups/joins on a column you filter or join on often
